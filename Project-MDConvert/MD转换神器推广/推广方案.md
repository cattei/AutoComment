## 一、产品画像

### 1.1 一句话定位

**万物皆可 Markdown** —— 拖入文件夹，一键批量转 MD，免费、免安装、本地处理不上传。

### 1.2 核心卖点（按说服力排序）

| # | 卖点 | 说明 | 话术示例 |
|---|------|------|----------|
| 1 | **完全免费** | 无功能限制、无水印、无次数限制 | "完全免费，不限文件数，不限格式" |
| 2 | **单 exe 零安装** | 双击即用，不装 Python、不装依赖 | "一个 exe，复制到任何电脑就能用" |
| 3 | **批量+保持目录** | 递归扫描，转换后目录结构一模一样 | "100 个文件夹？一键全转，目录结构不变" |
| 4 | **15+ 格式** | docx/doc/xlsx/xls/pptx/ppt/pdf/html/txt/csv/xml/json/md/rst/rtf + 图片 | "Word、Excel、PPT、PDF……15 种格式一网打尽" |
| 5 | **图片提取+OCR** | 自动提取 docx 图片，DeepSeek-OCR 识别图中文字 | "连图片里的字都能识别出来" |
| 6 | **本地处理** | 文件不上传服务器，隐私安全 | "文件在你电脑上处理，不上传任何服务器" |

### 1.3 目标用户画像

| 用户群 | 痛点 | 场景 | 规模感 |
|--------|------|------|--------|
| **AI/LLM 用户** | 喂语料要手动复制粘贴，格式乱 | 把文档批量转 MD 喂给 AI、建 RAG 知识库 | ⭐⭐⭐⭐⭐ 最大盘 |
| **知识管理党** | Obsidian/Notion 导入 Word/PDF 格式不对 | 把现有文档库迁移到 MD 笔记系统 | ⭐⭐⭐⭐ |
| **技术写作者** | 文档从 Word 迁移到 MD，手动转太慢 | 技术文档、API 文档格式迁移 | ⭐⭐⭐ |
| **企业文档数字化** | 大量历史文档要数字化、结构化 | 批量转换内部文档，配合搜索引擎/知识库 | ⭐⭐⭐ 付费潜力大 |
| **学生/教师** | 课件、论文格式转换 | PPT→MD 做笔记，论文→MD 存档 | ⭐⭐ 长尾 |

### 1.4 竞品分析

| 竞品 | 类型 | 优势 | 劣势 | 我们的差异化 |
|------|------|------|------|-------------|
| **markitdown CLI** | 命令行 | 微软官方，稳定 | 需装 Python，无 GUI，无批量，无 OCR | ✅ GUI + 批量 + OCR + 免安装 |
| **Pandoc** | 命令行 | 格式最全，生态强 | 需安装，学习成本高，无 OCR | ✅ 零门槛 + OCR + 批量 |
| **各种在线转换网站** | Web | 免安装 | 上传文件=隐私风险，有大小/次数限制，速度慢 | ✅ 本地处理 + 无限制 + 批量 |
| **WPS/Word 导出** | 软件 | 格式保真 | 只能单文件，无批量，无 OCR | ✅ 批量 + OCR + 目录保持 |
| **Obsidian 插件** | 插件 | 生态内 | 仅限 Obsidian 用户，格式支持有限 | ✅ 通用 + 格式多 + 独立运行 |

**核心差异化总结：免费 + 免安装 + 批量 + OCR + 本地安全，这个组合市面上没有竞品能做到。**

## 二、商业模式

### 2.1 免费使用 + 自愿打赏

| 层级 | 内容 | 目的 |
|------|------|------|
| **免费层** | 全功能无限制使用 | 零门槛获客，建立信任 |
| **打赏层** | 微信收款码，"请我喝杯咖啡" | 信任变现，不设门槛 |

### 2.2 打赏转化路径设计

```
用户发现工具 → 免费使用 → 觉得好用 → 触达打赏入口 → 自愿打赏
```

**打赏入口布局（5个触点）：**

| # | 位置 | 时机 | 文案 |
|---|------|------|------|
| 1 | 转换完成弹窗 | 每次转换完成 | "转换完成！觉得好用请我喝杯咖啡 ☕" |
| 2 | README 底部 | 查看 GitHub 时 | "如果这个工具对你有帮助，欢迎打赏支持！" |
| 3 | 公众号文末 | 阅读文章后 | "觉得有用？请作者喝杯咖啡，支持持续更新" |
| 4 | 小红书评论区置顶 | 看到推荐后 | "免费无限制～觉得好用可以请我喝杯咖啡" |
| 5 | 软件内 hover 彩蛋 | 使用过程中 | "请我喝一杯吧"（已有，hover 显示微信码） |

**关键原则：打赏文案用"请我喝杯咖啡"，不用"打赏"/"赞助"——前者是请客，后者是交易，心理感受完全不同。**

## 十、风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| OCR API 额度用完 | 中 | 用户 OCR 功能不可用 | README 说明 OCR 为可选功能，核心转换不依赖 API |
| 被人搬运到收费渠道 | 高 | 品牌受损 | README 明确"免费工具"，GitHub 开源可验证 |
| 推广内容被限流 | 中 | 曝光不足 | 多平台分散，不依赖单一渠道 |
| 打赏收入为零 | 高 | 无直接收入 | 正常预期，先攒用户和口碑，收入是副产品 |
| exe 被杀毒软件误报 | 中 | 用户不敢下载 | 代码签名（成本高，后期考虑），README 加说明 |

## 十一、关键提醒

1. **"免费"是最大武器** —— 每个文案都要突出"完全免费"，打赏是自愿的，别让用户觉得有隐藏收费
2. **场景 > 功能** —— 别说"支持15种格式"，要说"你的毕业论文、周报、课件，一键全转MD"
3. **GIF 是转化率之王** —— 比任何文字都有说服力，优先搞出来
4. **GitHub 是信任基石** —— 开源 + Star 数 = 可信度，先把这个阵地守好
5. **打赏文案用"请我喝杯咖啡"** —— 不用"打赏"/"赞助"，前者是请客，后者是交易
6. **版本更新 = 推广素材** —— 每次更新都是发内容的好时机
7. **多平台分散风险** —— 不把鸡蛋放一个篮子，任一平台限流不影响全局
8. **先做再完美** —— 第一版素材不用完美，先发出去看数据，再迭代
